# 01 · WSL2

> 一句话：WSL2 是 Windows 上跑的一个真 Linux 内核（轻量虚拟机），Docker Desktop 的 Linux 容器
> 实际都跑在它里面。**它不是"模拟器"，所以 `df`、`free`、`ps` 看到的都是它自己的资源，
> 与 Windows 宿主隔离** —— 这条是后面所有内存问题的根源。

---

## 一、通用知识

### 1.1 WSL1 与 WSL2 的本质差别

| | WSL1 | WSL2 |
| --- | --- | --- |
| 实现 | 系统调用翻译层（`lxss`） | Hyper-V 轻量虚拟机，跑真 Linux 内核 |
| 文件 I/O | 访问 Windows 文件快，访问 Linux 文件一般 | **访问 Linux 侧文件快，跨 `/mnt/c` 极慢** |
| 系统调用兼容性 | 不全（Docker 跑不起来） | 完整 |
| 内存 | 与宿主共享 | **独占一块虚拟内存，默认最多 50% 物理内存** |

结论：要跑 Docker 就必须 WSL2；而一旦用 WSL2，内存就是**配额制**，不是按需。

### 1.2 `.wslconfig`（全局配置，只有一份）

位置固定在 `C:\Users\<你>\.wslconfig`（**不是**发行版里的 `/etc/wsl.conf`，后者管的是
systemd、默认用户、挂载选项这类发行版内部行为）。

```ini
[wsl2]
memory=10GB                   # 整个 WSL2 VM 的内存上限
processors=8                  # 分几个核
swap=2GB                      # 交换分区大小
swapFile=D:\wsl\swap.vhdx     # 交换文件放哪（默认在 C 盘）
[experimental]
autoMemoryReclaim=gradual     # 空闲内存逐步还给 Windows
sparseVhd=true                # 虚拟磁盘按需增长，不预占
```

两个必须知道的规则：

1. **改完要 `wsl --shutdown` 才生效**（会关掉所有发行版和 Docker Desktop 的后端）。
2. **`memory=` 是上限，不是预留**。设 10GB 不代表立刻吃掉 10GB；但容器真的用满时，
   Windows 会开始换页，宿主变卡。所以配额要按「容器合计 + 系统开销」倒推。

### 1.3 磁盘：VHDX 只增不减

WSL2 的根文件系统是一个 `ext4.vhdx`。删文件**不会**让它变小 —— 里面是 ext4，
外面是稀疏虚拟盘，两者不联动。

```powershell
# 压缩（需先 wsl --shutdown）
wsl --shutdown
Optimize-VHD -Path D:\Docker\DockerDesktopWSL\disk\docker_data.vhdx -Mode Full   # 需 Hyper-V 模块
# 或者用 diskpart 的 compact vdisk
```

### 1.4 跨文件系统的性能悬崖

`/mnt/d/...` 走的是 9p（或 drvfs）协议，每次 `stat` 都要过一层转发。实测差距：

- 在 `/home` 下 `git status` 一个中型仓库：< 0.5s
- 同样仓库放 `/mnt/d` 下：10s+

**推论**：数据库数据目录、Docker 卷，**不要**放在 `/mnt/*` 上。本项目正是踩了这个坑
（见下）。

### 1.5 常见用法

```bash
wsl -l -v                 # 列出发行版与状态（Running / Stopped）
wsl --shutdown            # 关掉所有发行版（改 .wslconfig 后必经）
wsl --status              # 默认发行版、内核版本
wsl --version             # WSL 自身版本
wsl -d Ubuntu-22.04       # 进指定发行版
```

`wsl.exe` 在 `C:\Windows\System32\`。**这条会带来一个副作用**：Windows 的 `PATH` 里
`System32` 优先，所以在 PowerShell 里敲 `bash` 命中的是 WSL 的启动器，而不是 Git Bash
（详见 `05`）。

## 二、在本项目中

### 2.1 配额：10GB 怎么来的

宿主 15.7GB 物理内存，Windows 自身 + 浏览器 + IDE 需要 5~6GB，因此 WSL 给 10GB：

```ini
[wsl2]
memory=10GB
processors=8          # 16C32T 的一半，留出宿主响应
swap=2GB
swapFile=D:\wsl\swap.vhdx
```

10GB 里的分配：

| 用途 | 大小 |
| --- | --- |
| 6 个容器 limit 合计 | 8.75GB（8960MB） |
| dockerd + containerd + WSL 内核 | ~1.25GB |

这个余量只有 1.25GB，是**紧的**。曾经算过一版"6 容器 9.5GB / 余 512MB"的方案，
结论是不能上 —— 见 `02` 里 `docker stats` 的读法。

### 2.2 磁盘放 D 盘

C 盘当时只剩 33.8GB，而 Docker 的镜像层 + 6 个容器的数据要 10GB 以上，所以：

```
Docker Desktop → Settings → Resources → Advanced → Disk image location
  = D:\Docker\DockerDesktopWSL
```

**换位置只影响以后新拉的数据**，已有数据要用 Settings 里的迁移（它会做一次导出导入）。
本项目是重装后重新拉的镜像，比迁移干净。

### 2.3 踩过的坑

**坑 1：9p 文件系统的 `statvfs` 返回假数据**

早期把 Doris BE 的 `storage` 目录 bind mount 到 `/mnt/d/...`，BE 一启动就报
`a broken disk is found`，然后无限重启。查下来：

```
$ df -T /mnt/d/...
Filesystem  Type  ...
D:          9p    ...

$ df -i /mnt/d/...
Filesystem  Inodes  IUsed  IFree
D:          ...     999  -999001     ← 负数！
```

9p 驱动对 `f_files` / `f_ffree` 的返回值是垃圾，Doris 用它算"磁盘是否可用"，
于是判定全盘损坏。`df -h` 完全看不出来，**必须 `df -T` 看类型、`df -i` 看 inode**。

修法：BE 的 `storage` 改用 Docker 命名卷（落在 WSL 的 ext4 上，`df -i` 有 6700 万 inode）。
这也是全项目**唯一**用命名卷的地方，其余组件（MySQL / Kafka）是 bind mount 到
仓库内的 `docker/volumes/`，那也在 ext4 上，没问题。

**坑 2：`wsl --shutdown` 之后再起，作业全没了**

WSL 重启 = Docker 引擎重启 = Docker Desktop 的后端重启，但**容器策略是 `restart: "no"`**，
所以 6 个容器不会自动起；Flink 是 session 集群，作业定义只存在 JM 内存里，容器一起来
`/jobs/overview` 就是空数组。

判据：6 个容器 `StartedAt` 完全相同且 `RestartCount=0` → 是"新起的集群"，
不是"作业崩了"。恢复只需 `bash scripts/demo.sh --no-dashboard`。

**坑 3：内存告警不在 WSL 侧**

容器被 cgroup OOM Kill 时，WSL 的 `dmesg` 里往往什么都没有（杀手是 cgroup，不是内核 OOM killer）。
真正的证据在 `docker inspect <容器> --format '{{.State.OOMKilled}} {{.RestartCount}}'`。
本项目 TM 被 OOM 过两次，都是这样定位的（见 `12`）。

## 三、速查

```bash
# 配置
notepad "$USERPROFILE/.wslconfig"      # PowerShell
cat /c/Users/$USER/.wslconfig          # Git Bash

# 生效
wsl --shutdown                          # 会连 Docker Desktop 一起停

# 资源现状
free -h                                 # WSL 里看到的"物理内存"= memory= 的值
nproc
df -T ; df -i ; df -h                   # 查文件系统类型与 inode，不要只看 -h

# 磁盘位置
# Docker Desktop → Settings → Resources → Advanced → Disk image location
```

| 现象 | 判据 | 处理 |
| --- | --- | --- |
| BE 报 `a broken disk is found` | `df -T` 是 `9p`、`df -i` 的 `IFree` 是负数 | 数据目录换命名卷 |
| 容器全没了 | `StartedAt` 全同 + `RestartCount=0` | 是重启不是崩溃，重跑 `demo.sh` |
| 宿主卡顿 | `docker stats` 合计接近 `memory=` | 降容器 limit，别加 `memory=` |
| 磁盘只涨不降 | `ext4.vhdx` 体积 | `wsl --shutdown` 后 compact |
