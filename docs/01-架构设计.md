# 架构设计

## 1. 为什么是双数据源

单一数据源做不出真实数仓的样子：

| 数据源 | 承载的业务 | 技术通道 | 典型延迟 |
| --- | --- | --- | --- |
| MySQL 业务库 | 订单、支付、商品、卖家、评价 | Flink CDC（binlog） | 秒级 |
| 用户行为日志 | 浏览、搜索、加购、结算 | Kafka + Flink | 毫秒~秒级 |

两条链路在 DWD 层汇合，才能做出「行为 → 转化 → 成交 → 履约」的完整链路指标。

## 2. 分层职责

```
ODS  贴源，只做结构化和元信息补全，不做业务清洗
DWD  明细，去重 / 过滤 / 维表打宽 / 派生字段，粒度 = 业务最小单元
DWS  汇总，按 分钟 / 小时 / 日 预聚合，供 ADS 与自助分析复用
ADS  应用，面向具体看板与报表，指标口径在此固化
```

约束：

- **跨层引用只允许自上而下单向依赖**，DWS 不直连 ODS
- ADS 不允许直接查 DWD 明细做实时聚合（会拖垮查询），必须走 DWS
- 维度表统一放 DWD，ODS 不再维护维表冗余

## 3. 时间语义（本项目最关键的约定）

每张明细表同时保留两个时间戳：

| 字段 | 含义 | 来源 | 用途 |
| --- | --- | --- | --- |
| `event_time` | 业务真实发生时间 | 业务字段 / 事件自带 | 所有窗口聚合、分区归属 |
| `proc_time` | 进入数仓的时间 | `NOW()` / Kafka 消息时间 | 延迟监控、数据质量 |

由此可以推出两个指标，并且拿到大屏的「链路健康度」面板：

- `ingest_lag = proc_time - event_time` → 端到端延迟
- `迟到比例 = count(ingest_lag > 阈值) / count(*)` → 数据质量

如果只保留一个时间戳，迟到数据要么被静默丢弃，要么污染窗口结果且无法定位。

## 4. 幂等与一致性

| 环节 | 手段 |
| --- | --- |
| Kafka 生产 | 固定 `event_id`，允许重复发送，由下游去重 |
| ODS 落库 | Doris Unique Key（Merge-on-Write），同主键自动覆盖 |
| Flink Checkpoint | 30s 间隔，RocksDB 增量，落本地文件系统 |
| 写入 Doris | Flink Doris Connector 两阶段提交，Checkpoint 成功才提交事务 |
| 重放 | 支持按时间区间重跑，重跑结果与原结果一致（幂等验证用例） |

> 简历上可以写的一句话：**「链路在模拟 3% 消息重复 + 5% 乱序 + 迟到 5 分钟的注入下，指标结果与无脏数据基线完全一致。」** 这比「保证了 exactly-once」有说服力得多。

## 5. 迟到数据与乱序

- Flink 侧：`watermark` 延迟 30s，`allowed lateness` 5 分钟，迟到窗口触发更新
- Doris 侧：DWS 采用 Aggregate 模型，迟到数据的聚合值以 `REPLACE` / 累加方式回写
- 兜底：整点跑一次「补数作业」修正前 N 小时的 DWS

## 6. 资源预算（16GB 内存）

WSL2 上限锁在 **10GB**（见 `docs/04` §4），容器 limit 之和必须压在 10GB 以内。

| 组件 | 内存 limit | 说明 |
| --- | --- | --- |
| Doris FE | 1.5 GB | 单 FE，元数据 + 查询规划 |
| Doris BE | 3 GB | 单 BE，`replication_num=1`，`mem_limit=70%` |
| Flink JobManager | 768 MB | 只做协调 |
| Flink TaskManager | 2 GB | 2 slots，RocksDB 状态后端 |
| Kafka（KRaft） | 768 MB | 单节点，单分区起步 |
| MySQL 8 | 768 MB | `innodb_buffer_pool_size=256M` |
| **合计** | **≈ 8.8 GB** | 余下约 1.2GB 给 WSL 内核与 dockerd |

> 数据量只有 121MB，大内存没有收益。压缩 limit 是为了避免宿主机 swap——swap 落在 D 盘 vhdx 上，比内存慢两个数量级。

### 启动顺序（分三类 profile，不要一次全起）

```bash
docker compose --profile source  up -d   # mysql + kafka
docker compose --profile compute up -d   # flink jm + tm
docker compose --profile olap    up -d   # doris fe + be
```
